### 1. Addy Osmani：Critical thinking when agents do the work（X Article）

- 原帖：[addyosmani](https://x.com/addyosmani/status/2117512471930167377)（北京时间 2026-11-03 15:01 发布）
- 数据：展示 2,077,277，点赞 10,986，收藏 26,185（收藏率约 1.26%），转发 1,618，引用 518
- 形态：X Article，约 1.8 万字符，正文引用 Anthropic 研究、Wharton 的 cognitive surrender 论文和作者自己的多篇博客

**分节忠实翻译（关键段落）**

> **开头**：以前，批判性思维被教成用谦逊的好奇心和适度的怀疑去面对新信息：听不同的观点，形成自己的看法。这话现在仍然对，但我的工作越来越多经过 agent，日常里已经没有什么会逼我做批判性思考。我很喜欢这些工具，写这篇不是劝大家少用 agent。我的目标是帮你在什么都能甩给 agent 的世界里保住批判性思维。
>
> 过去，我们大部分认知和审美加工发生在「提问到答案」之间的那段空白里。现在这段空白按秒计算。模型越好，明显错误的比例越低。很多（大多数？）输出写得好、基本正确，但不会逼你再看一眼。你同时跑再多 agent，盯着输出的也只有你一双眼睛。批判性思维得主动排进你的一天，因为默认情况下没有任何东西会替你做。

> **卸载、顺从与投降**：我把它描述成一条光谱。最上面是认知卸载：把任务交给 AI，但结果仍归你负责，我整天这么做，你也应该。中间是顺从：工具的输出成了你的新输入，结果不再是一个待验证的假设。最下面是认知投降：AI 的输出悄悄变成了你自己的，你觉得没必要检查。这个词来自 Wharton 的 Steven Shaw 和 Gideon Nave。人会随着信任（或懒惰）增加一路往下滑，而且很少察觉，因为每一步都很小、看起来都合理：上一个答案你读得很仔细，下一个就扫一眼，再下一个只看骨架，直到有人问你某一行，你连借助 agent 都解释不了。
>
> 我说的不是做不到的事。大型代码库的完整心智模型本来就装不下。Claude Code 团队公开说过，他们按需重建理解：需要哪一块，就让 Claude 讲哪一块。你不需要一直持有全貌，只要能在需要时局部重建，并且知道自己缺什么。低风险的事尽管整个委托。我挑录课酒店时就让 AI 帮我在三家评分差不多的酒店里选了一家，效果很好。但怎么投资、怎么给孩子职业建议、工作上做什么、改动影响哪些用户、能不能安全上线，这些我不会交出去。出错代价低的地方接受交接，后果要别人承担的地方，把推理留在自己手里。

> **我现在问自己的问题**：提问前我先有假设了吗？在跑任何非琐碎任务之前，我先写下（哪怕只在脑子里）我认为答案可能是什么，猜错也没关系；一旦读了一篇写得很好的回答，就很难再想象别的可能。完全没头绪时，可以让模型做一次「盲点扫描」：把你知道的给它，让它找出你不知道自己不知道的东西。我是在让它帮我想，还是在替我想？两种都行，但要知道自己在做哪一种。要让它错，什么必须成立？然后去查；模型对自己信心的评估远不如一个你真能执行的测试。我听过换个角度的反方论证吗？立场强硬的开放问题，我会让不止一个模型去论证反方，再自己下判断。我敢当着要维护它的人为它下注吗？这是可问责的门槛。我不再练的是什么？比如一部分日常排错，我可以放掉，但要是有意放掉的。

> **把验证变成习惯**：我觉得瓶颈已经从写代码转移到确认自己是对的。给 agent 验证手段（端到端测试、属性测试、真实操作应用），它就能改、跑、读输出、再试，全程不用你看。Boris Cherny 把这叫「给 Claude 一个验证自己工作的办法」。你也可能交出验证本身：「有证据支持我的结论吗」变成「检查变绿了吗」。测试便宜到到处都是绿灯，但测试和功能犯同一个错时照样会过，而且一个绿灯只证明一个性质。每看到一个绿灯，说出它检查了哪个性质，再说出一个它没检查的。事先定义什么叫「验证过」，因为事后你会为任何结果找理由；收尾物要具体：测试通过、截图、日志或 trace。收到 agent 完成通知时，先看它执行的命令和输出，再看总结。我每次收尾还会问一句「我漏了什么吗？」，它常常再给出两三条。我最喜欢 Claude Code 团队 code review 文章里的一条经验：「如果你说不出检查会漏掉什么，就要一次真正的 review，而不是快速批准。」这条也适用于代码之外：agent 替你综合了 50 通客户电话，就抽查几份原始材料；你的建议依赖某个数字，就亲自核一下它怎么算的。

> **真正去看生成了什么**：agent 给你一个 600 行的 PR，你大致看了结构，变量名合理、测试通过，你批准了。可中间藏着一个事务边界的顺序变化，或者一个你没想到的边界情况被翻转了默认值。你确实 review 了，但只 review 了你本来就知道要找的东西。写代码和审代码是两种技能。像审别人代码一样读 diff，再越过 diff 看 agent 替你做了哪些决定：默认值、什么算范围外、两个需求冲突时它重新解释了哪一个。让它列出所做的决定和假设，然后考自己：随机挑几行问自己这行干什么；文档就合上后凭记忆写出主论点。有人在长会话结束时让 Claude 写一份改动报告，末尾附小测验，规则是「满分才合并」。还有产量问题，我叫它编排税：agent 生成的量和你愿意署名的量之间的差距。如果完成的工作堆得比你看得快，再开一个会话也没用，要么收紧检查让更少的东西需要你，要么放慢。产出超过你能负责的量时，你已经不是在审查，而是在祈祷。

> **输入的质量决定输出的质量**：人的心智模型仍在，但从中间挪到了开头和结尾：开头是任务描述和上下文，结尾是审查输出。以前你提一个含糊的请求，会有人追问，你才发现自己没想清楚；agent 往往不会拦你，它把空缺补上，交回一个看起来完成了的东西，背后的想法仍是模糊的。我把这叫意图债：没人能替你还，意图必须来自你。你的 prompt 反映你对问题的理解，写不清楚，可能就是自己没想清楚。求助前先用自己的话写一份需求简报：受众、范围外的事、完成的定义。第二轮修改还没到位，就别再微调，重写 prompt。也要小心输入：每个 agent 都把上一个 agent 的总结塞进上下文，很快第三个 agent 根本没读过原始文档。输出也要有自己的标准：现在什么都格式漂亮、语气自信，精致已经不是有用的信号。如果我不愿意把它署上自己的名字，我就不发。某样东西没达标时，把原因写进共享配置、hook 或测试，避免重犯，这就是品味的复利。

> **「模型以后会比我更会做这些」**：检测这件事你可能说得对，我自己也一直主张把更多检测交给 agent。但最终总有人要为上线的东西负责。该多信任 agent 本身就是判断，而保持校准的一部分就是亲自审查，因为模型犯的错一直在变。Anthropic 对自家工程师和研究员的研究把这叫监督悖论：「监督 Claude 需要的正是可能因过度使用 AI 而退化的编码技能。」做什么、为什么值得、影响谁、愿意牺牲什么，这些问题更好的模型也替你答不了。你可以卸掉工作和大部分审核，但卸不掉责任。

> **日常练习**：不必全做，挑适合你工作流的。每周不用 agent 写一点代码，或者做一件忘了就会很糟的真事。每月写下你已经不做的事，决定哪些可以接受不做。问自己：如果没有 AI，你会有多迷茫？碰到超出理解的东西就去学。认真检查机器的产出是真实的工作，把它当成排期里的一项。不练的技能会消失，可能比你想的快。

> **带走什么**：有意为之，agent 能考你、采访你、给你看证据，但前提是你去设置。诚实面对自己在光谱上的位置。先有假设。一个绿灯只代表一件事。先看证据再看总结。读出它替你做了哪些决定。认真写 prompt。设一条线并守住，不愿署名就不发。动手之前写下你预计会发生什么，agent 做完后写下一件它没检查的事。

**详细总结**：全文围绕一个现象：模型越好，明显错误越少，人就越容易从「交出任务」滑到「交出判断」，而且自己察觉不到。作者把它拆成卸载、顺从、投降三档，给出的判断标准很简单：借助 agent 都解释不了的答案，就已经不归你了。对策分四块：提问前先有假设、主动找反方；把验证定义在动手前，并对每个绿灯说清楚查了什么、没查什么；读 diff 之外再读 agent 替你做的决定，用小测验逼自己理解；把精力放到开头的需求简报和结尾的署名标准上，并把每次不达标的原因写进配置或测试。最后一段回应「模型会更强」的反驳：检测可以交出去，责任交不出去。

**为什么会传播**：作者是长期写 AI 编码方法的一线实践者，用第一人称讲自己的做法；题目切中「重度用 agent 的人越来越不想看输出」这个普遍焦虑；正文是可以直接照抄的问题清单和习惯清单，收藏率 1.26% 说明大量读者存下来要回头用；引用 Anthropic 研究和 Claude Code 团队的说法，可信度高。

**写作可借鉴**：用一条三档光谱给模糊的焦虑命名（卸载、顺从、投降），读者能马上对号入座；每个抽象原则都配一个日常场景（挑酒店可以交出去，给孩子职业建议不行；600 行 PR 里藏着一个被翻转的默认值）；结尾把全文压成一组短句清单，方便收藏和转述。
