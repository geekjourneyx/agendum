### 1. DeepSeek Harness：《Super-agent 设计探索：迈向更自主的 Agent 系统》

- 原帖：[DeepSeekHarness](https://x.com/DeepSeekHarness/status/2116857257245987236)（X Article，北京时间 2026-11-01 19:37 发布）
- 数据：展示 1,979,579，点赞 11,090，转发 1,364，引用 637，回复 371，收藏 13,877（收藏率约 0.70%）
- 形态：约 43,000 字符的长文；文首说明原文为中文，这里是机器翻译，并说明「本文讨论架构思路，不是 DeepSeek Harness 现有功能介绍」
- 相关原型：[deepseek-ai/dsh-superagent-prototype](https://github.com/deepseek-ai/dsh-superagent-prototype)

**关键段落翻译（分节忠实节译）**

> **1. Super-agent**：过去一年，coding agent 等单任务 agent 证明了模型可以用工具解决复杂问题，需要人持续盯着、逐步干预的地方越来越少……但主流 agent 设计仍以单个 session 为基本工作单位，session 之间彼此隔离。用户并行跑几个任务时，要手动在 session 间切换，还要记住每个 session 里有什么。根据经验，一个人通常同时只能跟住 3 到 5 个活跃 session。用这些设计，单个任务受限于模型能力，多任务却受限于人的注意力。
>
> Super-agent 有四个基本特征：**连续**（用户在 IM、GitHub 评论等原本工作的地方直接交互，始终感觉是同一个 agent）；**高产**（响应快，并行完成多个复杂任务，上一条没做完就能接下一条）；**主动**（不等逐步指令，监听环境事件，值得处理就处理，否则保持安静）；**持久**（始终在线，接入真实工作环境，长期运行中能从异常里自动恢复）。
>
> **2. 双层架构**：所有事件都送进一个 session，上下文最连续，但 ReAct 循环一次走一步，吞吐低，不同任务的中间细节还会混在一个上下文里；每个事件都开新 session，吞吐最高，但缺共享上下文，几个 session 分别回复用户也让交互混乱。解法是分两层：长期存活的 Router 层处理所有人类交互和全局协调，上下文隔离的 Worker 层高并发执行任务。让用户手动管理 session，很大程度上是从底层 LLM API 带过来的设计习惯。session 应该是系统的实现细节，不该是用户的心智负担。
>
> **2.1 Router 层**：为了不让唯一的全局节点成为瓶颈，Router 层被设计成自己不执行任务，只和人交互、分派任务，甚至可以不带 Bash 工具。经验上 Router 的活比想象中简单，较轻的模型通常就能兼顾速度和质量。一次推理期间到达的事件会排队，在下一轮合并处理，形成批处理，开销增加很少。
>
> **2.2 Worker 层**：每个 Worker 有隔离的上下文和全套执行工具，专做一个任务，通常需要最强的模型。Worker 从不直接和人交互，只向 Router 汇报状态，所有对用户的回复都由 Router 负责。
>
> **3.1 事件过滤**：接上真实群聊和代码平台后，系统看到的是噪音大、触发率低的事件流，绝大多数日常消息不需要 agent 动作。借用计算机系统的 Fast Path / Slow Path：程序策略按来源、群、用户或机器人白名单做快速准入，每个来源可以设为「只回应明确请求」「当候选事件」或「忽略」；只有通过的候选事件才交给大模型按提示词里的策略判断。
>
> **3.2 事件路由**：同一个 PR、IM 话题或邮件链上的连续事件组成一个 Thread。Router 为 Thread 的第一个事件创建 Worker 后，Worker 直接订阅该 Thread，后续事件由代码直通给 Worker，不再经过 Router。
>
> **3.3 上下文组织**：把有限的上下文窗口当缓存。Inline 是把很快要用的信息直接放进窗口，Spill 是把超预算或不常用的完整信息放在窗口外，只留引用或摘要。先给最少的信息（对象 ID 和内容摘要），再按局部性逐步加入相关内容，超长内容截断并留指针。所有对象都有 ID、互相引用，模型可以沿着引用一跳一跳找回上下文，即「链式召回」。
>
> **3.4 提前行动**：借用推测执行。内部用户群里配了「静默复现并修复」策略：有人报问题时，agent 先在后台尝试复现和找修复，只有确认问题、找到简单修复才交付，否则全程不出声。
>
> **4. 全双工多渠道**：把耗时的工具调用换成异步的 start() 和 stop()，前台对话不被后台任务阻塞（DeepSeek Harness 已实现，默认未开启）。IM 渠道要尽量少打扰人，只在需要决定或签字时通知，只问直接的问题，只给简短结论；验证过的一条简单硬规则是每条回复不超过 100 个词。GitHub、邮件、文档等异步渠道则给结构化、信息密度高的输出。
>
> **5. 计算、状态、环境分离**：Agent Loop 的计算放在无状态的云端容器，session 状态放数据库；执行环境留在原地，每台机器只装一个不保存状态的轻量 daemon，支持接入用户自己的机器（BYOM）。
>
> **6. Watchdog**：很多异常不是崩溃，进程还在，但模型卡在无效循环里或偏离了目标。所以用一个独立的、由定时消息驱动的 Watchdog session，既处理 API 错误等基础设施故障，也用模型判断每个 Worker 是否有实质进展。
>
> **7. 初步实验**：约 300 条消息、约 20 个工作请求，每种方案跑 5 次，编码工作用一个只消耗时间的工具模拟，只测调度协作。Super-agent 任务完成时间 p50 12.4 分钟、p95 15.7 分钟。中性提示的单 Session 方案 5 次里一次都没调用子 agent，p95 达到 29.5 分钟；「委派优先」提示 5 次里 4 次委派，另 1 次模型认为活「很小」自己做了，拖出长尾。去掉直通后完成时间相近，但 Router 每次多做约 30% 的决定，cache-read token 从 23.2M 增至 31.8M（约 +37%）。Router 压测里，需要决定的 Trigger 从约 1 条/分钟升到约 40 条/分钟，平均批大小从 1.0 到 2.8，单次请求时间从 2.5 秒到 3.9 秒，单个决定分摊推理时间从 6.4 秒降到 1.6 秒。原文说明这是合成负载，结果只作参考。
>
> **8. 未解问题**：双层架构如何扩展、长期记忆（运行数月后成为主要瓶颈）、没有 session 的产品形态怎么设计、上下文边界与 A2A 通信、安全与隐私。只要终端上的凭据能进入模型上下文，正常执行也可能把它泄露出去，agent 需要一种「用凭据但看不到凭据」的方式。
>
> **9. 结论**：这份设计没有提出新理论，而是把计算机系统的经典工程思想用到 agent 系统上。随着单任务需要的人工干预越来越少，生产力的瓶颈正在转向人的注意力。

**详细总结**：文章的主线是「瓶颈从模型能力转到人的注意力」。为此 DeepSeek 把 agent 从「一个窗口一个 session」改成一个常驻实体：Router 只管说话和分派，Worker 只管干活；事件先用代码过滤再交给模型；后续事件直通给负责的 Worker；上下文按缓存思路管理；后台先做，确认有用再出声；计算、状态和执行环境分离，外加一个独立的看门狗。最有分量的是两组实验数字：单 session 能否委派完全看提示词和模型当场判断，双层架构把这件事从提示词层面挪到系统层面解决。

**为什么会传播**：DeepSeek 一手出品，题目对准「下一代 agent 长什么样」；每一节都借一个计算机系统的老概念（快慢路径、缓存、推测执行、存算分离、看门狗），读者有现成的抓手；有对照实验和具体数字；结尾坦白安全问题没解决，可信度更高。

**写作可借鉴**：用「旧概念 + 新问题」组织长文，每节一个经典系统概念对应一个 agent 问题，读者不用学新词就能跟上。把结论落成一条可执行的硬规则（例如「每条回复不超过 100 个词」），比泛泛说「要少打扰人」更容易被引用。

> 关于识别那些可怕的、没有灵魂的、正在侵入互联网每个角落的 AI 生成文字，有一点是这样的：它不只是关于用词——而是关于模式。

>
> 多余的破折号。圆滑的过渡。总是三个一组的例子。

> 那些似乎说得通又似乎说不通的怪比喻——就像一顶在潜水艇里打开的降落伞。

>
> 随机的一句话段落。
>
> 一堆平淡的废话被悄悄重新包装成深刻洞见的方式。
>
> 持续-不断、毫无-必要地给日-常词语加连字符。
>
> 陈词滥调。
>
> 再读一遍。
>
> 陈词滥调。
>
> 后排的大声点。
>
> 成堆的陈词滥调。
>
> 这不是笔误。
>
> 和这句话待一会儿。
>
> 最大的危险信号呢？自问自答。
>
> 因为说实话？没有哪个有知觉的人类会这样写。
>
> 而且说真的？如果你认不出这些危险信号，你自己可能都不算有知觉。
>
> 因为真的？如果这种格式没让你立刻觉得别扭和造作，说明你不读书。
>
> 从来不读。
>
> 认真的。
>
> 但有意思的地方来了：
>
> 并没有。
>
> 道理已经讲完了，但我还要继续。AI 写作就是这样。
>
> 让我们深入（delve）真正的问题。问题不在技术。在于用它的人，他们（原文此处为侮辱性用词）蠢到想不出一个自己的原创想法。
>

>

>
> 但这是没人告诉你的事。
>
> 当你让机器替你制造个性时，你不只是在自动化你的写作。你是在悄悄宣布：你是个无聊、乏味、没什么有趣的话可说的呆子。
>
> 让这句话沉淀一下。
>
> 令人不安的真相？
>
> AI 并没有把这些人变成乏味的庸人。
>
> 它只是悄悄揭示了他们本来的样子。
>
> 也许——只是也许——这才是悄悄地最重要的收获。
>
> 但你怎么看？我们在评论区一起拆解一下。👇

**写作可借鉴**：这篇等于一份 AI 文风的反面清单：多余破折号、三个一组、半通不通的比喻、一句话成段、自问自答、「不只是 A，而是 B」、「让这句话沉淀一下」、「但有意思的地方来了」。改稿时可以拿它逐条自查。另一个技巧是「用被批评的形式来批评它」，形式和内容互相证明，比正面列规则更有记忆点。
